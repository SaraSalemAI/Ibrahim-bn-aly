# SUMED P2P — Rules, controls, statuses and KPI library

_Generated by `node tools/gen-docs.js` from the engine dictionaries._ All thresholds referenced here are configurable in **Settings** and are **illustrative defaults, not SUMED policy**.

## Three-way match statuses (precedence order)

1. **DUPLICATE** — Duplicate
2. **MISSING PO** — Missing PO
3. **EXCEPTION** — Exception
4. **MISSING GRN** — Missing GRN
5. **QUANTITY VARIANCE** — Quantity variance
6. **PRICE VARIANCE** — Price variance
7. **TAX VARIANCE** — Tax variance
8. **PARTIALLY MATCHED** — Partially matched
9. **MATCHED** — Matched

PARTIALLY MATCHED is used when only header-level matching is possible (no line data). Tolerances: price %, quantity %, tax-rate percentage points and an absolute rounding tolerance.

## Duplicate detection levels

- **EXACT DUPLICATE** — same supplier + same invoice number + same amount & currency, or identical file hash.
- **HIGH-RISK DUPLICATE** — same supplier and same number after normalisation (prefixes, separators, leading zeros removed) with amount within tolerance; or same supplier & amount within the high-risk window with same PO / similar description / identical lines; or different supplier records with the same normalised number, amount and bank account. Escalated when both documents were paid.
- **POSSIBLE DUPLICATE** — same supplier, similar amount within the window plus similar description or same PO; same number for a different supplier; identical line items.

Signals: `sameSupplier` same supplier · `sameInvoiceNo` same invoice number · `normalisedInvoiceNo` same number after normalisation · `sameAmount` same amount · `similarAmount` amount within tolerance · `dateWithin` dates n day(s) apart · `samePO` same PO · `sameFileHash` identical file hash · `similarDescription` description n% similar · `sameBankAccount` same bank account · `identicalLines` identical line items · `bothPaid` BOTH PAID · `sameBankReference` same bank reference · `sameInvoicePaidTwice` same invoice paid twice · `invoicesAreDuplicates` underlying invoices flagged n

## Recommended actions

- `recoverDuplicate` — Stop / recover the duplicate amount from the supplier; block the second document.
- `holdDuplicate` — Put the later invoice on hold; confirm with the supplier before approval.
- `verifySupport` — Obtain and verify supporting documents before approval/payment.
- `confirmAuthorisation` — Confirm the authorisation and business reason; document the exception.
- `callbackVerify` — Independent call-back to the supplier on master-file contact; hold payments until verified.
- `reviewSplit` — Review for threshold avoidance; re-route through the correct approval tier.
- `blockPayment` — Block further payments; investigate and recover if unsupported.
- `obtainGRN` — Obtain goods/service receipt before further payments.
- `reconcile` — Obtain bank reference and reconcile against the bank statement.
- `investigateSupplier` — Investigate supplier identity and relationships; block until cleared.
- `mergeSuppliers` — Confirm whether records are the same entity; merge and block the duplicate.
- `renegotiate` — Challenge the price increase; renegotiate or re-tender.
- `taxReview` — Tax review against configured rates and supplier tax registration.
- `contractAmend` — Stop new orders; amend/renew the contract or re-tender.
- `arrangeFunding` — Re-sequence payments or arrange funding / FX conversion before the gap date.
- `remediateControl` — Assign control owner; remediate exceptions and re-test.
- `fixData` — Correct the source data and re-upload.
- `payOrSchedule` — Approve for the next payment run.
- `reviewBeforePay` — Compliance/procurement review before releasing payment.
- `expediteApproval` — Escalate approvals to avoid late payment.
- `renewOrRetender` — Start renewal or re-tender; confirm continuity of supply.
- `obtainDocuments` — Request updated documents; suspend new POs if not received.

## KPI library (formula · unit)

| KPI | Formula | Unit |
|---|---|---|
| Total Outstanding AP | `SUM(outstanding × FX rate at as-of date) over open invoices` | EGP |
| Overdue AP | `SUM(outstanding base) WHERE as-of date − due date ≥ 1` | EGP |
| Current (not yet due) AP | `SUM(outstanding base) WHERE due date ≥ as-of date` | EGP |
| Average payment days | `Σ(days invoice→payment × net base) / Σ net base` | days |
| On-time payment rate | `payments made on/before due date ÷ payments with a due date` | % |
| Largest supplier share of AP | `largest supplier outstanding ÷ total AP` | % |
| Total supplier spend (12 months) | `SUM(amount × FX at document date)` | EGP |
| Non-PO spend | `SUM(spend) WHERE no PO reference` | EGP |
| Off-contract spend | `SUM(spend) WHERE document date outside referenced contract window` | EGP |
| Maverick spend | `SUM(spend) WHERE non-PO OR off-contract OR supplier not approved` | EGP |
| Emergency spend | `SUM(spend) WHERE emergency/urgent flag` | EGP |
| Contract spend | `SUM(spend) WHERE contract reference present` | EGP |
| Top-5 supplier concentration | `Σ spend of 5 largest suppliers ÷ total spend` | % |
| DPO | `DPO = Average AP ÷ Purchases × Days` | days |
| Suppliers in master | `COUNT(supplier master rows)` | count |
| Active / approved suppliers | `COUNT WHERE status ∈ {Approved, Active}` | count |
| Critical suppliers | `COUNT WHERE Critical flag = Yes (SOURCE VALUE)` | count |
| High / critical-risk suppliers | `COUNT WHERE risk rating ∈ {HIGH, CRITICAL} (explainable risk model)` | count |
| Payments due ≤ 7 days (incl. overdue) | `SUM(outstanding base) WHERE due date ≤ as-of + 7` | EGP |
| Due today or overdue | `SUM(outstanding base) WHERE due date ≤ as-of` | EGP |
| Payments scheduled (not executed) | `SUM(net × FX) WHERE status ∈ {Approved, Scheduled, Submitted to Bank}` | EGP |
| Payments executed (30 days) | `SUM(net × FX) WHERE executed/reconciled AND payment date ≥ as-of − 30` | EGP |
| Payment register total | `SUM(net × FX at payment date)` | EGP |
| Cash required — 13 weeks | `Σ scheduled payments + approved unpaid invoices due within 91 days (at latest FX)` | EGP |
| Invoice exceptions (3-way match) | `COUNT WHERE match status ∉ {MATCHED, PARTIALLY MATCHED}` | count |
| Duplicate invoice risk (exposure) | `Σ amount of the later invoice in each flagged pair` | EGP |
| High / critical fraud & anomaly alerts | `COUNT(alerts) WHERE severity ∈ {HIGH, CRITICAL}` | count |
| Remaining contract value (active) | `Σ (contract value − invoiced against contract) × latest FX` | EGP |
| Average invoice processing time | `AVG(approved date − received date)` | days |
| Average payment cycle (invoice → payment) | `AVG(payment date − invoice date)` | days |
| PO compliance | `invoices with PO ÷ all invoices` | % |
| Three-way match rate | `MATCHED ÷ PO-backed invoices` | % |
| Invoice match rate | `(MATCHED + PARTIALLY MATCHED) ÷ invoices` | % |
| Exception rate | `exceptions ÷ invoices` | % |
| Duplicate rate | `invoices flagged as later member of a duplicate pair ÷ invoices` | % |
| Late payment rate | `payments after due date ÷ payments with due date` | % |
| Contract compliance | `contract invoices within contract window ÷ contract invoices` | % |
| Average supplier risk score | `AVG(supplier risk score)` | /100 |
| Discount capture rate | `payments within discount window ÷ payments on discount terms` | % |
| Potential savings (quantified) | `Σ quantified opportunities (see Cost Reduction for method & confidence)` | EGP |
| Control failures | `COUNT(control tests with status FAIL)` | count |
| Payment forecast — 30 days | `Σ scheduled + approved + pending invoices + PO commitments dated within 30 days` | EGP |
